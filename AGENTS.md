# Architecture rules
- Keep recruiter Question bank styling scoped to its page and dialogs using recruiter-backed semantic tokens; preserve existing question services and action handlers so learner screens remain unchanged.
- Keep research data behind src/data/papers.ts and use the existing file router and TopNav; sample summaries must never claim live AI generation or credit deductions.
- Keep learner profile settings in the existing profile route using shared UI controls and theme tokens; preserve browser-only profile overrides and never present unconnected security actions as successful account changes.
- Reopen mock interview reports through the existing InterviewReport view using slug-scoped session snapshots; never substitute sample scores for a missing past report.
- Keep the supplied learner hero self-contained and verbatim; the dashboard supplies the signed-in first name and navigation, and `/java-lab` redirects to the existing Java lab to avoid duplicating its workspace.
- Keep ticket review pages scoped by lab and ticket, render only captured submission files, and leave unrecorded performance metrics pending; temporary session snapshots are not persisted grading reports.
- Keep system design lab metadata and sprint definitions in `src/lib/systemDesign.ts` so the catalog, admin seeds, and learner sprint view stay aligned.
- Dispatch system design tickets to the shared `SystemDesignStudio` at the ticket-view boundary so direct links and admin previews use the same workspace.
- Scope design studio drafts by lab slug and ticket ID so work cannot leak between tasks; retain the standalone studio as a separate sandbox.
- Keep system-design ticket criteria in systemDesign metadata and shared evaluation contracts in lib/evaluation; use one right-side drawer, prefer explicit ticket criteria, fall back to actual requirements, and leave unvalidated criteria pending rather than inventing grades.- Keep the recruiter GitHub and repositories page flat and card-free (hairline dividers, GitHub mark as the only icon, orange primary button) using `gh-theme` tokens scoped in src/styles.css; preserve all connect/sync/disconnect/switch/search/filter and "Use in lab" handlers in GithubSettingsTab.
- Keep the yuvrolabs pricing page at the flat route `/yuvrolabs-pricing` (src/routes/yuvrolabs-pricing.tsx); do not nest it under `/yuvrolabs` since that route renders no Outlet, and keep all plan pricing in constants at the top of the file.
- Keep recruiter evaluation cards and list rows in one rendering path with shared action handlers so switching views never drops details or functionality.
- Keep contest scheduling and reward pricing in pure tested lib modules, with a replaceable in-memory data layer and React-only state; label preview transactions so they cannot imply real registration or reward activation.
